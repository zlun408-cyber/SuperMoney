# 交易记录编辑 / 删除 UI 设计文档

## 1. 目标
在第二阶段现有“交易记录可新增”的基础上，补齐“编辑单条记录”和“删除单条记录”的页面交互，让用户可以直接在基金详情页维护交易明细，并在修改后自动看到重算结果。

## 2. 范围
### 包含
- 在详情页交易记录列表中增加“编辑”“删除”操作
- 复用现有交易记录弹层，同时支持“新增模式”和“编辑模式”
- 编辑时自动回填原记录内容
- 编辑时允许切换记录类型
- 删除前显示确认提示
- 编辑或删除后自动刷新详情页和首页汇总结果
- 补充对应单测

### 不包含
- 首页直接编辑交易记录
- 自定义复杂确认弹窗
- 更复杂的字段级红字校验系统
- 交易记录拖动排序

## 3. 交互设计
### 3.1 交易记录列表
每条交易记录右侧增加两个按钮：
- 编辑
- 删除

### 3.2 新增模式
延续现有交互：
- 点击“添加交易记录”
- 打开交易记录弹层
- 标题显示“添加交易记录”
- 底部主按钮显示“保存记录”

### 3.3 编辑模式
- 点击某条记录的“编辑”
- 打开与新增共用的弹层
- 标题显示“编辑交易记录”
- 底部主按钮显示“保存修改”
- 表单自动回填原记录内容
- 允许修改记录类型，并随类型切换对应字段

### 3.4 删除模式
- 点击某条记录的“删除”
- 先弹出浏览器确认框
- 确认文案：`确认删除这条交易记录吗？删除后会自动重算持仓和收益。`
- 确认后删除，并自动重算详情页与首页结果

## 4. 数据与状态设计
### 4.1 存储
继续复用现有 `transactions` 数组，不新增额外存储结构。

### 4.2 页面状态
在详情页内容层维护“当前正在编辑的记录”：
- `null`：当前是新增模式
- 某条交易记录：当前是编辑模式

### 4.3 调用方式
详情页接入现有 hook 能力：
- `addTransaction`
- `updateTransaction`
- `removeTransaction`

新增、编辑、删除都通过现有 watchlist 状态统一落盘。

## 5. 组件设计
### 5.1 `AddTransactionDialog`
升级为通用表单组件：
- 支持新增模式
- 支持编辑模式
- 支持接收默认值
- 支持根据模式切换标题和按钮文案
- 支持保存后关闭
- 支持取消编辑并清空状态

### 5.2 `TransactionList`
升级为带操作按钮的列表组件：
- 展示记录基本信息
- 对外暴露编辑回调
- 对外暴露删除回调

### 5.3 `FundDetailContent`
负责连接页面状态：
- 管理当前编辑中的记录
- 传入新增 / 编辑 / 删除回调
- 在记录变化后自动重算现有汇总卡

## 6. 错误处理
- 表单字段不完整：阻止保存，保留当前弹层
- 卖出份额超出可用份额：沿用现有计算层错误
- 删除取消：不做任何修改
- 记录类型切换：按新类型重新解释字段显示，但不保留已不适用字段

## 7. 测试策略
- 组件测试：验证编辑模式回填、保存修改、删除按钮触发
- 页面测试：验证详情页点击编辑/删除后数据变化
- 回归测试：确认首页和详情页仍优先显示交易记录推导结果

## 8. 成功标准
完成后，用户应当能够：
1. 在详情页看到每条交易记录的编辑/删除入口
2. 编辑一条记录并保存修改
3. 删除一条记录并确认删除
4. 在编辑或删除后立即看到汇总结果自动更新
