# 第三阶段：登录与云同步设计文档

## 1. 目标
第三阶段把当前“仅保存在浏览器本地”的基金监控工具，升级为“登录后可长期使用”的产品版本。核心目标不是单纯增加登录入口，而是解决以下真实问题：

- 换设备后数据不丢
- 换浏览器后还能继续使用
- 自选基金和交易记录可以长期积累

## 2. 第三阶段范围
### 包含
- 用户注册
- 用户登录
- 用户退出登录
- 自选基金列表云端保存
- 交易记录云端保存
- 登录后自动恢复云端数据
- 首次登录时处理本地数据与云端数据关系

### 暂不包含
- 忘记密码
- 邮箱验证
- 导入导出
- 自动合并冲突数据
- 多人共享
- 高级权限系统
- 复杂账户中心页面

## 3. 产品原则
- 登录只是手段，核心价值是“数据不丢”
- 第三阶段先做最小闭环，不追求一次做全
- 汇总结果继续运行时计算，不在云端保存快照
- 冲突处理优先安全，不做自动合并

## 4. 需要同步的数据
第三阶段先只同步最核心数据：

1. 自选基金列表
2. 每只基金的交易记录
3. 基础用户身份信息

第三阶段先不同步：
- 页面 UI 偏好
- 临时刷新状态
- 本地缓存数据
- 复杂统计快照

## 5. 本地与云端数据关系
### 5.1 初次登录场景
首次登录时分三种情况处理：

#### 情况 A：云端没有数据，本地有数据
- 直接把本地数据上传到云端
- 作为用户第一份云端数据

#### 情况 B：本地没有数据，云端有数据
- 从云端下载数据到当前设备
- 作为当前设备初始化数据

#### 情况 C：本地和云端都有数据
- 不自动合并
- 提示用户选择覆盖方向

### 5.2 冲突处理方式
当本地和云端都有数据时，给用户两个明确选项：

- 使用云端数据
- 使用本地数据

提示说明：
- 使用云端数据：当前设备会恢复云端已有数据
- 使用本地数据：当前设备数据会上传并覆盖云端

这样可以最大程度避免误删或误合并交易记录。

## 6. 技术路线
第三阶段推荐技术方向：

- 前端：Next.js
- 认证与数据库：Supabase

选择 Supabase 的原因：
- 适合当前阶段快速搭起登录和数据保存
- 认证与数据库一体化，减少基础设施工作量
- 对 Next.js 集成友好
- 后续继续做同步、统计、报表时也比较顺

## 7. 云端数据结构
第三阶段采用“两张核心表”的方案，而不是把所有数据存成一整块 JSON。

### 7.1 `watchlist_funds`
存自选基金：
- `id`
- `user_id`
- `code`
- `name`
- `created_at`

### 7.2 `fund_transactions`
存交易记录：
- `id`
- `user_id`
- `fund_id`
- `type`
- `trade_date`
- `amount`
- `shares`
- `nav`
- `fee`
- `note`
- `created_at`
- `updated_at`

### 7.3 结构选择理由
采用两张表而不是大 JSON，有这些好处：
- 结构清晰
- 更容易做局部更新
- 更容易做筛选、统计和后续扩展
- 与当前“交易记录驱动”的计算方式更一致

## 8. 页面与交互建议
第三阶段先增加这些用户可见入口：

- 顶部登录入口
- 顶部退出登录入口
- 未登录时提示“登录后可同步数据”
- 首次登录冲突时显示轻量选择框
- 登录后自动恢复云端数据

第三阶段先不做复杂账户中心页面。

## 9. 数据流建议
### 9.1 未登录时
- 继续使用本地数据
- 保持当前产品可直接使用

### 9.2 登录后
- 拉取云端数据
- 根据本地/云端情况执行初始化或冲突处理
- 之后用户对自选基金和交易记录的改动，同步写入云端

### 9.3 渲染层
- 首页和详情页仍然只消费当前 watchlist 数据
- 持仓汇总、已实现收益、未实现收益继续由前端运行时计算
- 不额外保存“汇总快照”

## 10. 风险与边界
### 10.1 当前阶段先不处理的复杂问题
- 多设备同时修改冲突
- 云端版本历史
- 自动合并交易记录
- 离线编辑后复杂同步策略

### 10.2 当前阶段控制范围的原因
这些问题都重要，但如果第三阶段一次全做，会明显拖大范围。第三阶段的首要任务是先把“登录 + 云同步 + 数据恢复”闭环跑通。

## 11. 第三阶段成功标准
当第三阶段完成后，用户应当能够：

1. 注册并登录
2. 把自选基金和交易记录保存到云端
3. 换浏览器或换设备登录后恢复数据
4. 首次登录遇到本地/云端冲突时，自己选择覆盖方向
5. 不影响现有首页、详情页和交易记录计算逻辑

## 12. 推荐实现顺序
建议按下面顺序推进：

1. 接入认证
2. 建立云端表结构
3. 打通登录后拉取与写入
4. 处理首次登录冲突选择
5. 回归验证首页、详情页、交易记录流程
