# 基金交易明细驱动收益系统（第二阶段）设计文档

## 1. 目标
第二阶段把当前“手工录入持仓汇总”的方式升级为“交易明细驱动”的方式。用户可以为单只基金记录买入、卖出、现金分红、红利再投资，并由系统自动计算当前持仓、已实现收益、未实现收益和相关汇总结果。

## 2. 第二阶段范围
### 包含
- 单只基金录入多条交易记录
- 支持四类记录：买入、卖出、现金分红、红利再投资
- 采用先进先出（FIFO）计算卖出成本与已实现收益
- 自动计算当前剩余份额、当前持仓成本、平均成本
- 自动计算已实现收益、未实现收益、累计分红、累计卖出回收
- 详情页展示交易记录列表与持仓汇总
- 首页基于交易记录展示汇总结果
- 基础校验与错误提示
- 支持编辑和删除单条交易记录

### 暂不包含
- 税务口径报表
- 图表系统
- 导入导出
- 云同步
- 多账户隔离

## 3. 核心记录类型
### 3.1 买入
字段：
- 交易日期
- 买入金额
- 买入净值
- 手续费（可选）
- 备注（可选）

系统自动计算：
- 买入份额

### 3.2 卖出
字段：
- 交易日期
- 卖出份额
- 卖出净值
- 手续费（可选）
- 备注（可选）

系统自动计算：
- 卖出到账金额
- 本次卖出已实现收益

### 3.3 现金分红
字段：
- 交易日期
- 分红金额
- 备注（可选）

系统处理：
- 计入已实现收益
- 不增加份额

### 3.4 红利再投资
字段：
- 交易日期
- 分红金额
- 再投资净值
- 备注（可选）

系统自动计算：
- 新增份额
- 新增持仓层

## 4. 计算规则
### 4.1 先进先出（FIFO）
- 每次买入和红利再投资都会形成一层持仓
- 卖出时优先扣减最早形成的持仓层
- 一层扣完后，再扣下一层，直到卖出份额满足

### 4.2 当前持仓
系统根据未被卖出的剩余持仓层自动计算：
- 当前剩余份额
- 当前持仓成本
- 平均成本

### 4.3 收益
系统自动计算：
- 已实现收益：卖出收益 + 现金分红
- 未实现收益：当前市值 - 当前持仓成本
- 累计卖出回收
- 累计分红收益

### 4.4 校验规则
- 卖出份额不能大于当前可用份额
- 金额、净值、份额必须大于 0（按记录类型要求）
- 空字段不允许保存
- 日期必须有效

## 5. 页面设计
### 5.1 首页
首页继续做“结果页”，不做复杂交易编辑。

显示内容升级为：
- 基金名称、代码、当前估值、涨跌幅
- 当前剩余份额
- 当前持仓成本
- 未实现收益
- 必要时显示已实现收益简要值

### 5.2 详情页
详情页成为第二阶段核心页面，新增三块区域：
1. 持仓汇总卡片
2. 交易记录列表
3. 添加交易记录入口

### 5.3 记录录入方式
继续采用轻量交互：
- 点击“添加交易记录”
- 先选择记录类型
- 再显示对应字段
- 保存后刷新详情页和首页汇总

## 6. 数据方案
### 6.1 本地存储
第二阶段仍保存在浏览器本地。

新增保存内容：
- 每只基金的交易记录数组
- 按时间排序的记录
- 由记录推导出的展示结果不落库存快照，优先运行时计算

### 6.2 兼容第一阶段数据
- 已有 watchlist 结构需要扩展，但不能破坏现有基金列表
- 旧的“持仓汇总字段”可保留一段过渡期
- 第二阶段页面优先使用交易记录结果

## 7. 错误处理
- 卖出份额超出可用份额：提示“卖出份额不能大于当前可用份额”
- 没有交易记录时：提示“还没有交易记录，请先添加第一笔记录”
- 记录字段不完整时：阻止保存并提示缺失字段
- 单条记录删除后：立刻重算首页和详情页结果

## 8. 第二阶段成功标准
当第二阶段完成后，用户应当能够：
1. 为单只基金添加买入、卖出、现金分红、红利再投资记录
2. 在详情页查看完整交易记录
3. 系统自动按 FIFO 计算当前持仓与卖出收益
4. 在首页和详情页看到自动汇总的持仓与收益结果
5. 编辑或删除记录后，结果自动更新

## 9. 推荐实现方向
- 保持现有 Next.js App Router 架构不变
- 新增交易记录类型定义、FIFO 计算模块、本地存储扩展和详情页交易记录组件
- 先把“数据结构 + 计算逻辑 + 详情页录入/展示”做通，再补更复杂展示
