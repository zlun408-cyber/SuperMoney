# 交易记录错误提示与表单校验反馈设计文档

## 1. 目标
在现有交易记录新增/编辑功能基础上，补齐更明确的表单错误提示，让用户在保存交易记录时，能清楚知道是“哪个字段没填对”，以及“是不是因为卖出份额超过当前可用份额导致无法保存”。

## 2. 范围
### 包含
- 交易日期为空时提示
- 金额为空、非数字、或小于等于 0 时提示
- 净值为空、非数字、或小于等于 0 时提示
- 卖出份额为空、非数字、或小于等于 0 时提示
- 卖出份额大于当前可用份额时，显示业务错误提示
- 错误提示只在点击“保存”时触发
- 继续支持新增模式和编辑模式

### 不包含
- 边输入边实时校验
- 更复杂日期合法性校验
- 备注字段校验
- 多记录重复检测
- 首页级错误提示

## 3. 交互设计
### 3.1 字段级提示
字段不合法时，在对应输入框下方显示红色小字：
- 交易日期：`请选择交易日期`
- 金额：`请输入大于 0 的金额`
- 净值：`请输入大于 0 的净值`
- 份额：`请输入大于 0 的份额`

### 3.2 业务错误提示
当卖出份额超过当前可用份额时，在表单按钮上方显示一条整体错误：
- `卖出份额不能大于当前可用份额`

### 3.3 触发时机
- 首次打开表单时，不显示错误
- 点击“保存”后才执行校验并显示提示
- 再次点击“保存”时重新判断
- 暂不做输入过程中的实时提示

## 4. 职责划分
### 4.1 `AddTransactionDialog`
负责：
- 字段级校验
- 显示字段级错误
- 显示业务错误
- 在提交前阻止无效保存

### 4.2 `FundDetailContent`
负责：
- 结合当前基金已有交易记录，判断卖出是否超额
- 将业务错误校验能力传给表单
- 保存成功后继续维持现有自动重算行为

## 5. 技术设计
### 5.1 表单返回值
现有 `buildTransaction(...)` 只返回交易记录或 `null`，不够表达“具体错在哪”。
建议改为更清晰的表单校验流程：
- 先收集字段错误
- 若字段错误存在，直接显示
- 若字段通过，再构建交易记录
- 若是卖出，再执行业务校验

### 5.2 业务校验方式
在详情页基于当前 `transactions` 和 `calculateTransactionLedgerSummary(...)` 或轻量辅助逻辑，判断当前可卖份额。
为了避免编辑时把“自己原来的卖出记录”也算进去导致误判，编辑卖出记录时，业务校验应基于“去掉当前编辑记录后的其余记录”再计算。

## 6. 测试策略
- 组件测试：
  - 保存空日期时显示日期错误
  - 保存非法金额/净值/份额时显示对应字段错误
- 页面测试：
  - 卖出超额时显示业务错误，不保存记录
  - 修正后可成功保存
- 回归测试：
  - 现有新增、编辑、删除流程仍然正常

## 7. 成功标准
完成后，用户应当能够：
1. 在保存交易记录时看到明确字段错误
2. 在卖出超额时看到明确业务错误
3. 修正输入后重新保存成功
4. 不影响现有新增、编辑、删除与自动重算流程
