# 基金实时估值网站（第一阶段）设计文档

## 1. 目标
第一阶段要做一个“基金实时估值监控”网站，重点是让用户在一个自选列表里，分钟级查看自己关注基金的估值变化，并结合自己的持仓信息看到估算盈亏。

## 2. 第一阶段范围
### 包含
- 自选基金监控首页
- 单只基金详情页
- 通过基金代码添加基金
- 通过基金名称搜索并添加基金
- 本地保存自选基金和基础持仓信息
- 分钟级自动刷新估值
- 手动刷新入口
- 持仓汇总录入
- 估算盈亏计算
- 基础错误提示与失败兜底

### 暂不包含
- 用户登录
- 云同步
- 买入记录明细录入
- 高级收益分析
- 复杂图表系统
- 多数据源切换界面

## 3. 页面结构
### 3.1 监控首页
作用：作为用户打开网站后的主控制台。

展示内容：
- 基金名称
- 基金代码
- 当前估值
- 涨跌幅
- 更新时间
- 持仓金额 / 份额 / 成本（按录入情况显示）
- 估算盈亏
- 添加基金入口
- 手动刷新入口
- 刷新状态提示

### 3.2 基金详情页
作用：查看单只基金的更完整信息。

展示内容：
- 基金名称与代码
- 当前估值
- 涨跌幅
- 更新时间
- 当前持仓信息
- 估算盈亏
- 编辑持仓入口

### 3.3 添加 / 编辑界面
第一阶段建议采用弹窗或轻量表单，而不是独立复杂页面。

支持内容：
- 输入基金代码添加
- 搜索基金名称添加
- 填写基础持仓汇总信息

## 4. 数据方案
### 4.1 行情数据
第一阶段接入一个现成基金估值数据源，用于获取基金估值与更新时间。

设计要求：
- 数据获取逻辑独立封装
- 以后可以替换成别的数据源，而不需要大改页面逻辑

### 4.2 用户数据
第一阶段不做登录，用户数据先保存到当前浏览器本地。

保存内容：
- 自选基金列表
- 基础持仓汇总信息
- 本地页面设置（如有）

### 4.3 刷新方式
- 页面打开时先拉取一次最新数据
- 页面停留期间按分钟级自动刷新
- 提供手动刷新按钮

### 4.4 盈亏计算
网站根据“基金估值数据 + 用户录入的基础持仓信息”计算：
- 当前持仓价值
- 估算盈亏
- 对应涨跌变化

## 5. 错误处理
### 5.1 刷新失败
- 保留上一次成功数据
- 提示“本次刷新失败，当前显示的是上次数据”
- 显示上次更新时间

### 5.2 基金代码或名称无效
- 提示“没有找到这只基金，请检查代码或名称”
- 不写入自选列表

### 5.3 持仓信息不完整
- 允许先加入监控列表
- 持仓与盈亏区域显示“待填写”或“无法计算”

### 5.4 单只基金刷新失败
- 只标记该基金异常
- 不影响列表中其他基金的显示

## 6. 第一阶段成功标准
当第一阶段完成后，用户应当能够：
1. 建立并保存自己的基金监控列表
2. 在首页看到分钟级更新的基金估值
3. 查看单只基金详情
4. 录入基础持仓信息并看到估算盈亏
5. 刷新失败时得到明确提示，而不是整页不可用

## 7. 推荐实现方向
建议采用“监控主线优先”的做法：
- 先把自选列表、详情页、基础持仓、估算盈亏和分钟级刷新做通
- 再在后续阶段补买入记录明细、登录和同步能力

## 8. 推荐技术方向（用于后续实现计划）
为了降低第一阶段复杂度，建议使用：
- 前端：Next.js + TypeScript
- 样式：Tailwind CSS
- 本地存储：localStorage
- 数据获取：封装一个基金数据服务层

这个组合的好处是：开发快、适合页面型产品、以后扩展登录或后端时也比较顺。
